# Working in this repository

GameSkills owns the development workflow. Read `gameskills.toml` and check the
installed pin with `gameskills status` (or the locally built executable). Resolve
selected skills through the host when available. If this session does not expose
them, read canonical `gameskills/plugins/<package>/skills/<skill>/SKILL.md` as an
explicit source fallback and report that limit; do not claim native activation.
Use `gameskills:plan` for implementation and its focused lifecycle skills for
verification and delivery. Direct specialist requests retain their narrower scope.

Preserve the user's requested endpoint across interruptions. Implementation work
normally ends at a reviewable PR here; plan-only requests remain plan-only. Start
or resume a durable `gameskills delivery` task, bind the actual PR and any adopted
tracker, and observe delivery before reporting completion. Passing local commands
alone does not establish publication. Do not infer permission to merge from PR
creation, and do not add parallel agents without applicable authorization.

Author shared capabilities in `gamekit/`, current skills in `gameskills/plugins/`,
and game-owned rules/content with their games. `devtools/tests/fixtures/legacy/`
contains frozen compatibility inputs, not an active skill source. Preserve local
adopter overlays, recorded pins and historical evidence when updating skills.
