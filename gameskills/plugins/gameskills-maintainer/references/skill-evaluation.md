# Evaluate skills by forward behavior

## Candidate and cases

Pin canonical source, installed package artifact and client version; record the
actual model/effort, harness, configuration and relevant environment. Compare a
candidate with the current pack and a no-skill/solo baseline when useful. Keep
held-out tasks beyond authoring examples. Do not pass an expected fix, suspected
bug or desired answer to a forward evaluator unless the task requires it.

Use independent agents only when the session or applicable instructions authorize
delegation. Give each evaluator a realistic request, skill/candidate location and
minimum raw artifacts, with isolated output and bounded side effects. If independent
runs are unavailable, report that limitation; self-review is not independent
behavioral evidence. Keep evaluations out of consumer/source checkouts.

Test positive and negative selection, direct toolbox use, coexistence with local
instructions and actual end-to-end outcomes. Suitable first tasks include solo
documentation delivery, a UI capability used by two games, a bounded parallel wave,
and a verified mid-wave addition. Include a fresh Bevy project without GameKit and
an engine-only reproduction so monorepo assumptions become observable.

## Failure and boundary cases

Exercise ownership collisions, human streams, start versus merge blockers,
unavailable native/port resources, interrupted/resumed work, stale evidence,
rejected findings and changed bases. Check that source identity survives handoffs
and that stopped or dependency-skipped commands are never reported as passed.
Use the same task at creative levels 1–4: creative output should change while
rigor, task boundaries and authorization remain stable.

Native-client acceptance includes real installation/discovery, explicit and
implicit invocation, selected optional packages, local-skill coexistence, and two
projects using different pinned candidates. Exercise update, interruption/recovery
and removal without losing project ownership. Identical Markdown, parsed manifests,
model labels or copied package files do not prove Codex/Claude behavior.

## Cost and decision

Measure actual coordinator plus worker usage, available cache reads/writes, elapsed
time, retries, review rounds, correctness and corrective user interventions.
Missing fields are unavailable, not zero. Compare equivalent outcomes and models;
parallel elapsed-time gains may increase total cost. Avoid universal savings claims
from a few tasks or self-described model identity.

Review resulting code/artifacts and evidence directly. Diagnose failures, make
narrow changes supported by those failures and rerun affected cases with held-out
coverage retained. Recommend promotion, limited rollout or rejection with precise
known gaps. A structurally valid candidate remains unproven until behavior and
installation have been observed in the claimed environments.
